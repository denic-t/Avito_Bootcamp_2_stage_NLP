# Кандидатогенерация для поиска услуг Авито

По поисковому запросу решение отбирает до 50 объявлений из корпуса в 189 212 объявлений, которые дальше уходят на ранжирование. Метрика - Recall50.

| Решение | Recall50, локальная валидация | Recall50, бенчмарк |
|---|---|---|
| 50 случайных объявлений из локации запроса | `0.0430` | - |
| BM25 + фильтры + локация | `0.8516` | `0.82` |

## Запуск

1. Установить зависимости: `pip install -r requirements.txt`.
2. Скачать данные по [ссылке из задания](https://disk.yandex.ru/d/sNhfo0YOjGtufg) и положить три parquet-файла в папку `dataset/`.
3. Выполнить `solution.ipynb` сверху вниз. Блокнот сохраняет `answer.csv`.

Лемматизация корпуса кэшируется в `cache/`. Повторный запуск даёт тот же `answer.csv`: все случайные операции фиксированы `SEED = 42`.

## Данные и признаки

| Данные | Как используем | Почему |
|---|---|---|
| `search_query` | лемматизированный текст для BM25 | основной сигнал: хотя бы одно слово запроса есть в выбранном объявлении в 92% пар |
| `search_infm_params_text` | значения фильтров «Вид услуги» и «Тип услуги» как второй запрос BM25 | значение фильтра есть в параметрах выбранного объявления в 94-98% пар |
| `search_location_id` | пул кандидатов: своя локация и частые соседние города | в 93% пар объявление из города поиска |
| `item_title_raw`, `item_infm_params_text`, `item_description_raw` | один документ для BM25 | описание даёт больше совпадений со словами запроса, чем заголовок |
| пары «локация поиска - локация объявления» из train | граф соседних городов и областей | train показывает, куда пользователи реально ходят из каждой локации |

Сами объявления из train почти не пересекаются с корпусом: в нём есть только 6.6% объявлений train.

## Модели и алгоритмы

- Лемматизация `pymorphy3`.
- BM25 на разреженной матрице `scipy`, словарь - `CountVectorizer` из `scikit-learn`. Параметры BM25 `k1=1.2`(насыщение по частоте), `b=0.75`(Учёт длины документа).
- Скор кандидата: `BM25(текст запроса) + 1.0 * BM25(значения фильтров) + 20 * [объявление из локации запроса]`. Бонус локации ставит объявления своего города выше соседних.
- Пул кандидатов: объявления локации запроса и городов, на которые при поиске из этой локации приходится не меньше 0.5% выборов в train.


## Проверка качества до отправки

- В train нет `query_id`, поэтому запрос собираем группировкой по всем колонкам `search_*`.
- Откладываем 3000 запросов по одному на уникальный текст, как в бенчмарке, из локаций бенчмарка и с весами под распределение его локаций.
- Корпус валидации: корпус бенчмарка плюс 3008 релевантных объявлений отложенных запросов, которых в корпусе нет.
- Recall50 считаем по формуле из условия. Все варианты сравниваем на этой выборке, а параметры пула и соседства считаем только по оставшейся части train.

## Особенности данных и найденные ошибки

| Что обнаружено | Как учтено |
|---|---|
| У 17% запросов бенчмарка локация поиска - это область, в которой нет ни одного объявления корпуса | пришлось построить по train соответствие «область - города объявлений» |
| 7% выборов приходятся на объявления из соседнего города | в пул добавлены частые соседние города, а объявлениям своей локации дан бонус |
| Слова запроса и объявления стоят в разных формах: «принтеров» и «принтер» | пришлось лемматизировать тексты `pymorphy3`: сравнение по префиксам показало +5-12 п.п. совпадений |
| Объявления train почти не пересекаются с корпусом: в нём только 6.6% из них | от запоминания пар «запрос - объявление» пришлось отказаться, поиск идёт по тексту |
| Цена и координаты хранятся как `decimal`, идентификаторы легко потерять при приведении к числу | `decimal` приведён к `float64`, `item_id` и `query_id` хранятся строками |
| Без порога соседями становились все города, где был хоть один выбор: пул рос до 70 тыс. объявлений, а Recall50 падал | пришлось ввести порог: оставлены соседи с долей выборов от 0.5%, медианный пул сократился до 4.6 тыс., Recall50 вырос |
| Локальная оценка оказалась выше бенчмарка на 3 п.п.: 0.8516 против 0.82 | в бенчмарке больше запросов без фильтров, 63% против 48%, а фильтры дают основной прирост. Варианты сравниваются между собой по валидации с поправкой на этот сдвиг |
