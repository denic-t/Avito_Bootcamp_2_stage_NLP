# Кандидатогенерация для поиска услуг Авито

По поисковому запросу решение отбирает до 50 объявлений из корпуса в 189 212 объявлений, которые дальше уходят на ранжирование. Метрика - Recall50.

| Решение | Recall50, локальная валидация | Recall50, бенчмарк |
|---|---|---|
| 50 случайных объявлений из локации запроса | `0.0430` | - |
| BM25 + фильтры + локация | `0.8516` | `0.82` |
| векторный поиск, дообученный `rubert-tiny2` | `0.8084` | - |
| BM25 30 + векторный поиск 20 | `0.8833` | - |
| **ранкер LightGBM на пуле BM25 + векторный поиск** | **`0.8891`** | **`0.8687`** |
| ранкер CatBoost YetiRank, для сравнения | `0.8842` | - |

## Запуск

1. Установить зависимости: `pip install -r requirements.txt`.
2. Скачать данные по [ссылке из задания](https://disk.yandex.ru/d/sNhfo0YOjGtufg) и положить три parquet-файла в папку `dataset/`.
3. Выполнить `solution.ipynb` сверху вниз. Блокнот сохраняет `answer.csv`.

Базовая модель `cointegrated/rubert-tiny2` скачивается с Hugging Face, дообученные веса - из [GitHub Release](https://github.com/denic-t/Avito_Bootcamp_2_stage_NLP/releases/tag/model-v1) с проверкой SHA-256. Если веса недоступны, блокнот дообучает модель тем же кодом, это около 100 минут на CPU. С готовыми весами полный прогон занимает около 40 минут.

Лемматизация и эмбеддинги корпуса кэшируются в `cache/`. Повторный запуск даёт тот же `answer.csv`: все случайные операции фиксированы `SEED = 42`, LightGBM работает в режиме `deterministic=True`.

## Данные и признаки

| Данные | Как используем | Почему |
|---|---|---|
| `search_query` | лемматизированный текст для BM25, текст для векторного поиска | основной сигнал: хотя бы одно слово запроса есть в выбранном объявлении в 92% пар |
| `search_infm_params_text` | значения фильтров «Вид услуги» и «Тип услуги» как второй запрос BM25 и как часть текста для векторного поиска | значение фильтра есть в параметрах выбранного объявления в 94-98% пар |
| `search_location_id` | пул кандидатов: своя локация и частые соседние города | в 93% пар объявление из города поиска |
| `item_title_raw`, `item_infm_params_text`, `item_description_raw` | один документ для BM25, заголовок + фильтры + начало описания для векторного поиска | описание даёт больше совпадений со словами запроса, чем заголовок |
| пары «локация поиска - локация объявления» из train | граф соседних городов и областей | train показывает, куда пользователи реально ходят из каждой локации |
| пары «запрос - подкатегория выбранного объявления» из train | вероятность подкатегории по тексту запроса, его леммам и фильтру «Вид услуги» | у типичного частого запроса 87.5% выборов приходятся на одну подкатегорию |
| `item_rating`, `item_rating_reviews_count`, `item_price`, флаги контактов | признаки ранкера | показывают, какие объявления пользователи выбирают охотнее |

Сами объявления из train почти не пересекаются с корпусом: в нём есть только 6.6% объявлений train.

## Модели и алгоритмы

- Лемматизация `pymorphy3`.
- BM25 на разреженной матрице `scipy`, словарь - `CountVectorizer` из `scikit-learn`. Параметры BM25 `k1=1.2`(насыщение по частоте), `b=0.75`(Учёт длины документа).
- Скор кандидата BM25: `BM25(текст запроса) + 1.0 * BM25(значения фильтров) + 20 * [объявление из локации запроса]`. Бонус локации ставит объявления своего города выше соседних.
- Пул кандидатов: объявления локации запроса и городов, на которые при поиске из этой локации приходится не меньше 0.5% выборов в train.
- Векторный поиск: `cointegrated/rubert-tiny2`, дообученный на 120 тыс. пар «запрос - выбранное объявление» из train. Функция потерь - кросс-энтропия по косинусной близости, негативы - остальные объявления в батче. Модель выбрана за скорость.
- Ранкер: LightGBM `lambdarank` переупорядочивает объединение топ-200 BM25 и топ-200 векторного поиска и отдаёт топ-50.


## Проверка качества до отправки

- В train нет `query_id`, поэтому запрос собираем группировкой по всем колонкам `search_*`.
- Откладываем 3000 запросов по одному на уникальный текст, как в бенчмарке, из локаций бенчмарка и с весами под распределение его локаций.
- Корпус валидации: корпус бенчмарка плюс 3008 релевантных объявлений отложенных запросов, которых в корпусе нет.
- Recall50 считаем по формуле из условия. Параметры пула, соседство, вероятности подкатегорий и векторную модель строим только по оставшейся части train.
- Ранкер обучается на отложенных запросах, поэтому его качество оцениваем на двух фолдах: обучаем на одной половине запросов, считаем Recall50 на другой.

## Особенности данных и найденные ошибки

| Что обнаружено | Как учтено |
|---|---|
| У 17% запросов бенчмарка локация поиска - это область, в которой нет ни одного объявления корпуса | пришлось построить по train соответствие «область - города объявлений» |
| 7% выборов приходятся на объявления из соседнего города | в пул добавлены частые соседние города, а объявлениям своей локации дан бонус |
| Слова запроса и объявления стоят в разных формах: «принтеров» и «принтер» | пришлось лемматизировать тексты `pymorphy3`: сравнение по префиксам показало +5-12 п.п. совпадений |
| Объявления train почти не пересекаются с корпусом: в нём только 6.6% из них | от запоминания пар «запрос - объявление» пришлось отказаться, поиск идёт по тексту |
| Цена и координаты хранятся как `decimal`, идентификаторы легко потерять при приведении к числу | `decimal` приведён к `float64`, `item_id` и `query_id` хранятся строками |
| Без порога соседями становились все города, где был хоть один выбор: пул рос до 70 тыс. объявлений, а Recall50 падал | пришлось ввести порог: оставлены соседи с долей выборов от 0.5%, медианный пул сократился до 4.6 тыс., Recall50 вырос |
| Готовая `rubert-tiny2` без дообучения даёт только 0.3279 и в объединении с BM25 ухудшает результат | модель пришлось дообучить на парах из train: 0.8084 |
| Ранкер на топ-300 BM25 проигрывал простому объединению: объявления, которые находит только векторный поиск, в пул не попадали | пул ранкера - объединение топ-200 BM25 и топ-200 векторного поиска |
| Локальная оценка выше бенчмарка: на 3 п.п. у BM25 и на 2 п.п. у ранкера | в бенчмарке больше запросов без фильтров, 63% против 48%, а фильтры дают основной прирост BM25. Варианты сравниваются между собой по валидации с поправкой на этот сдвиг |
